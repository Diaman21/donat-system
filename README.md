# Donat System

Система управления закупкой донатов в мобильных играх. Цель — выявить оптимальные
паттерны «разогрева» телефонов и не «убивать» их ошибками, фиксируя все данные
в базу знаний.

## Компоненты
- **Telegram-бот** — оперативная работа (заказчик / оператор / модератор)
- **Веб-интерфейс (Vercel)** — аналитика и база знаний
- **Supabase** — БД + бэкенд

## Роли
| Роль | Возможности |
|---|---|
| 🛍️ Заказчик | вводит только игровой аккаунт + сумму заказа |
| 👨‍💼 Оператор | берёт заказы, привязывает телефон (4 цифры IMEI), фиксирует результат покупок |
| 🛡️ Модератор | полный доступ, редактирование, управление |

## Результат покупки
- ✅ `done` — выполнено
- ⚠️ `support` — короткая ошибка (повтор на следующие сутки)
- 💀 `long` — телефон умирает навсегда (берём следующий)

## Схема БД (`supabase/migrations/0001_init.sql`)
- `users` — участники бота и роли
- `purchase_categories` — типы закупок (`game_donate`, `vk_votes`), расширяемо
- `phones` — телефоны, ≤3 активных, идентификация по 4 цифрам IMEI
- `orders` — заказы (игр.аккаунт + сумма), 1 заказ → много покупок
- `purchases` — ядро аналитики: телефон + точное время + сумма + результат

### Ключевые правила (в БД)
- Максимум **3 активных** телефона (триггер)
- Уникальность IMEI **только среди активных** телефонов
- 💀 `long` автоматически переводит телефон в `dead` и сохраняет историю
- Разогревочные покупки можно делать без заказа (`purchases.order_id` nullable)

## Подключение нового Supabase-проекта
1. Создай проект на https://supabase.com/dashboard
2. Сообщи мне `project ref` (или подключи MCP к новому проекту) — я применю миграцию
   `0001_init.sql` через `apply_migration`.
3. После применения сгенерирую TypeScript-типы (`supabase/types.ts`).

### Альтернатива — через Supabase CLI
```bash
supabase link --project-ref <ref>
supabase db push
```
