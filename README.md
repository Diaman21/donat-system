# Donat System

Внутренний инструмент маленькой команды для учёта закупки донатов в мобильных играх.
Оператор закупает через **Apple Pay на iPhone**, бот фиксирует каждую покупку в базу.

**Цель — найти «зелёный коридор»:** сколько и на какие суммы (€) можно закупать на
телефоне, не получив ошибку Apple, чтобы телефоны жили дольше и приносили больше.

## Что это (и чем НЕ является)

Бот — **логгер закупок**. Оператор в личке вбивает каждую закупку кнопками → данные
копятся → бот отдаёт аналитику. Заказчики бота не касаются: заказы приходят команде
как раньше, вручную.

Есть и **простой список заказов** (скинул текст → отметил выполненным) — но это
внутренний список задач двух операторов, а не доска с заказчиками, карточками и
статусами. От такой доски отказались осознанно, как от «лишних переменных».

## Роли

| Роль | Возможности |
|---|---|
| 🛍️ `customer` | роль по умолчанию при `/start` = **без доступа** (не используется) |
| 👨‍💼 `operator` | привязывает телефоны, вбивает закупки, смотрит аналитику |
| 🛡️ `moderator` | всё то же + `/export` CSV |

Роль назначается вручную: `npx tsx src/db/set-role.ts <telegram_id> <role>`.

## Возможности бота

**Закупка** (пошагово, кнопками): телефон → категория (🎮 танки / 🗳 ВК) → игра
(Massive / Furious / своя) → сумма (€30 / €100 / своя; €2-разогрев только в Massive) →
результат (✅/⚠️/💀) → заметка → подтверждение → выбор интернета (📶/📡) записывает покупку.
Для ВК — счётчик мультизакупа (N одинаковых покупок за раз).

**Телефоны:** привязка по 4 цифрам IMEI + метка, ≤3 активных (триггер БД),
🧰 подготовленные (резерв вне лимита), ввод в работу, удаление резерва,
☠️ вынужденный вывод (возврат бюджета), post-mortem при смерти.

**Заказы — главный вход в работу:** `📥 Заказы` — открытые заказы + счётчики
выполненных, `🗑` отменить, `➕ Добавить`. Новый заказ автоматически постится
в группу с тегами команды.

`✅ Выполнить` запускает цепочку закупки. **Заказ может требовать несколько
закупок** — бот распознаёт состав из текста («Орден + Банки» = 2×€30, «Орден +
Прем год» = €30 + €105), оператор подтверждает кнопкой, и заказ закрывается,
только когда сделаны **все** позиции. Позиции можно разводить по разным
телефонам; при ⚠️/💀 счётчик не растёт и заказ висит открытым. Из заказа
цепочка короче — категорию и игру не спрашивают, они уже известны.

`🛒 Без заказа` — для разогрева €2 и всего, что вне заказов (там спрашивается всё).

**Поиск:** `🔍 Поиск по IMEI` — 4 цифры → была ли трубка в работе, с какой меткой,
статус и итоги. Показывает все совпадения (последние 4 цифры повторяются, а умершие
телефоны остаются в истории).

**Аналитика:** `/stats` (периоды), `/vk` (голоса по дням), `/period` (отчёт-проводник:
период → дни → телефоны дня → таймлайн), `/history` (вся история телефона),
`/recent`, `/export` CSV, откат последней записи.

**Автоматика:** ежедневная сводка в группу (12:00 МСК), **ежедневный полный бэкап**
(12:05 МСК — JSON со всеми таблицами + CSV покупок; история чата = архив), громкий
алерт «‼️ ВЫВОД БЮДЖЕТА» с пингом команды (бюджет выводится на 14-й день после первой
покупки, предупреждение с 12-го), уведомления об ошибках модератору.

## Результат покупки

- ✅ `done` — покупка прошла.
- ⚠️ `support` — временный отказ платежа («Dein Kauf konnte nicht abgeschlossen werden»),
  **телефон жив**, отлежка ~сутки → можно повторить.
- 💀 `long` — всплыл waiver-диалог «Bestätigung… vierzehn Tagen» = **телефон мёртв навсегда**.
  Убивает само появление окна, жать ничего не нужно. Точные тексты — в `CLAUDE.md`.

## Схема БД

Шесть рабочих таблиц: `users`, `purchase_categories`, `phones`, `purchases`,
`order_queue`, `bot_sessions`. Ядро аналитики — **`purchases`**: телефон +
точное время + сумма € + результат + игра + интернет + голоса.

**Правила в БД (триггеры):** ≤3 активных телефона · IMEI уникален только среди активных ·
💀 `long` автоматически переводит телефон в `dead` и запоминает убившую покупку.

Миграции — `supabase/migrations/0001…0011`, применяются **вручную** в Neon SQL Editor.

## Текущий статус (сентябрь 2026)

Система работает на проде, данные копятся ежедневно. Накоплено **519 покупок на €11 505**
по 45 телефонам (14 умерли от ошибки Apple, 17 выведены вручную, 3 в работе,
11 подготовлено в резерв).

### 🟢 Рабочий протокол танков (подтверждён 09.09.2026)

Главное открытие: **убивает не сумма покупки, а короткий интервал между покупками**
на одном телефоне.

| Интервал между покупками | Покупок | 💀 | Смертность | Деньги за 14 дней |
|---|---|---|---|---|
| < 6 часов | 11 | 4 | 36% | €36–246 |
| 6–12 часов | 17 | 3 | 18% | — |
| 12–20 часов | 16 | 2 | 13% | — |
| **20–36 часов** | **69** | **1** | **1.4%** ✅ | **€409–839** |
| > 36 часов | 30 | 3 | 10% * | €341–494 (мало слотов) |

\* все три смерти при >36 ч имеют внешнюю причину — длинная пауза сама по себе не вредит.

Вторая покупка за день опаснее первой **в 6 раз**: 1-я за день — 4.3% смертность
(6 из 139), 2-я — 25.9% (7 из 27).

**Протокол:** разогрев €2×2 через Massive → далее **€100/€105, ровно одна покупка
в сутки (интервал 22–28 ч), только Wi-Fi** → полные 14 дней до вывода бюджета.
Никогда не делать вторую покупку в тот же день и не тратить слот на €30.

**Подтверждение:** после фиксации протокола — **55 покупок и ноль смертей** за месяц
(до этого смертность была 7.9%). Рекорд — **€839** (…8094, выведен живым).
Нарушители правила интервала давали €242–246 и умирали за 6 дней.

### Прочее

- ⏳ Хорошо ведомые телефоны доживают до вывода бюджета, не умерев — истинный предел
  пока не измерен.
- 📱 Слабые модели (12 mini, 12, 14 Plus) не годятся под крупные суммы: €36–106.
- 🗳 **ВК на паузе** с конца июня 2026 — Apple заблокировали приложения ВК.

## Локальная разработка

```bash
cd bot
npm install
npm run typecheck
npm test
```

Локальный запуск бота (`npm run dev`) работает **только с отдельным тестовым ботом** —
токен в `TELEGRAM_BOT_TOKEN_DEV`. Причина: Telegram не даёт одному боту работать и по
webhook, и по long polling, поэтому запуск боевого токена снял бы webhook и прод
замолчал бы без единой ошибки. Без dev-токена запуск останавливается и объясняет,
что делать. Детали и засады — в [`bot/README.md`](bot/README.md).
