# HANDOFF — как продолжить работу без этой сессии

> Если доступ к ассистенту пропал (бан аккаунта, смена инструмента), всё нужное
> для продолжения лежит в этом репозитории. Ни бот, ни база от ассистента не зависят.

## Что от чего зависит

| Что | Где | От ассистента зависит? |
|---|---|---|
| Код и вся история решений | GitHub `Diaman21/donat-system` (приватный) | нет |
| Бот 24/7 | Vercel, проект из папки `bot/`, деплой с `main` | нет |
| База | Neon (Postgres), строка подключения в `DATABASE_URL` | нет |
| Секреты | `.env` локально + Vercel → Settings → Environment Variables | нет |
| Ежедневный бэкап | группа «Pattern_analyst 🧮», 12:05 МСК (JSON + CSV) | нет |

⚠️ Храни копию `.env` в менеджере паролей: в git его нет и быть не должно.

## С чего начать новому ассистенту или разработчику

1. Прочитать `CLAUDE.md` (для Codex и других — `AGENTS.md`, это та же карта).
   Там суть проекта, правила, протокол танков, текущий статус.
2. `TODO.md` — что сделано, что ждёт данных, что ждёт решения владельца.
3. `docs/db-schema.md` — схема, миграции `0001…0014`, восстановление из бэкапа.
4. `bot/README.md` — запуск, тесты, засады Vercel.

## Правила работы владельца (перенесены из локальной памяти ассистента)

- Общение по-русски, пошагово, со структурой; варианты — с рекомендацией.
- **План → ждать «ок» → код.** Без подтверждения код не меняется.
- После шага: `npm run typecheck` + `npm test` → коммит на русском → push → отчёт.
- **SQL-схема (DDL):** файл `supabase/migrations/000N_*.sql`, показать SQL,
  **спросить разрешение отдельно**, только потом применять (панель Neon у
  владельца заблокирована, применяется через `DATABASE_URL`).
- Данные важнее всего: ничего не выдумывать, сверять по базе, дубль опаснее потери.
- Числа для документов — только через `attempts()` из `corridor.ts` (см. CLAUDE.md).
- После правки `CLAUDE.md` пересобрать `AGENTS.md` sed'ом (не править руками).
